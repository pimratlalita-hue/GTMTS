# Product Requirements Document (PRD)
## Faculty Operating System (Faculty OS)
**ระบบบริหารจัดการองค์กรและสนับสนุนการตัดสินใจระดับคณะในมหาวิทยาลัยไทย**

---

## 1. Executive Summary & Vision
**Faculty OS** คือระบบปฏิบัติการดิจิทัลแบบรวมศูนย์ (Integrated Modular Platform) ที่ออกแบบมาเพื่อปฏิรูปการทำงานของคณะในมหาวิทยาลัยไทย โดยมุ่งเน้นการขจัดปัญหาคอขวด 3 ด้านหลัก:
1. **ลดภาระงานเอกสารของอาจารย์ (Faculty Unburdening):** เปลี่ยนการจัดทำภาระงาน (TOR) และการประกันคุณภาพ (AUN-QA / OBE) จากงานเอกสารปลายปี ให้กลายเป็นระบบดิจิทัลอัตโนมัติ
2. **เร่งรัดกระบวนการอนุมัติและงบประมาณ (Operational Agility):** ปลดล็อกงานธุรการผ่าน Digital Workflow และการกันงบประมาณผูกพัน (Encumbrance) แบบเรียลไทม์
3. **สนับสนุนการบริหารเชิงรุก (Data-Driven Governance):** รวมศูนย์ข้อมูลจากระบบทะเบียน (SIS) และบุคคล (HRIS) สู่ Executive Cockpit เพื่อแจ้งเตือนความเสี่ยงนักศึกษาตกออก และติดตาม KPI คณะได้ทันที

---

## 2. Problem Statement & Pain Points (Top 5)
1. **Data Silos & Duplicate Data Entry:** ข้อมูลกระจัดกระจายอยู่ใน Excel/Google Sheets ของฝ่ายต่างๆ อาจารย์ต้องกรอกข้อมูลเดิมซ้ำหลายระบบ
2. **Faculty Workload & Performance Bottleneck:** การคิดภาระงาน/TOR/ก.พ.อ. ล่าช้า อาจารย์เสียเวลากว่า 20-30% ต่อรอบประเมิน 6 เดือน
3. **QA & OBE Compliance Overhead:** การเก็บรวบรวมหลักฐาน มคอ.3–มคอ.7, CLO/PLO, Rubrics ทำแบบเร่งด่วนก่อนตรวจประเมิน ข้อมูลไม่สะท้อนคุณภาพจริง
4. **Project Budget & Approval Friction:** การขออนุมัติโครงการวิจัย/จัดซื้อ/เดินทาง ต้องเดินแฟ้มลายเซ็นหลายขั้น งบประมาณค้างท่อ เบิกจ่ายไม่ทันสิ้นปี
5. **Lack of Executive Visibility & Early Warning:** ผู้บริหารขาดข้อมูล Real-time ในการตัดสินใจ รู้ตัวช้าเมื่อนักศึกษาติด Pro หรือถอนตัว

## 3. User Personas & Roles (RACI Matrix)

| Role / Persona | หน้าที่ความรับผิดชอบหลัก | ความต้องการสำคัญในระบบ |
| :---| :---| :---|
| **Faculty Member (อาจารย์ผู้สอน/นักวิจัย)** | สอนหนังสือ, ผลิตผลงานวิจัย, บริการวิชาการ, ส่งเกรดและรายงาน มคอ. | ไม่ต้องการกรอกข้อมูลซ้ำซ้อน, อยากให้ระบบดึงข้อมูลสอนและงานวิจัยมาคำนวณ TOR ให้อัตโนมัติในคลิกเดียว |
| **Head of Department (หัวหน้าภาควิชา)** | บริหารจัดการภาควิชา, ตรวจประเมินคะแนน TOR และผลการสอน | เห็นความคืบหน้าของอาจารย์ในสังกัด, ตรวจสอบหลักฐานและกดอนุมัติ TOR ได้สะดวกรวดเร็ว |
| **Curriculum Chair (ประธานหลักสูตร)** | ควบคุมมาตรฐาน AUN-QA, กำหนด PLO/CLO, ประเมินผลลัพธ์การเรียนรู้ | ตรวจสอบการบรรลุ PLO/CLO ของนักศึกษาแต่ละรุ่น, รวบรวมหลักฐานและสร้างรายงาน มคอ. แบบอัตโนมัติ |
| **Support Staff (ฝ่ายแผน/การเงิน/วิชาการ)** | เดินเรื่องคำร้อง, จัดซื้อจัดจ้าง, ควบคุมงบประมาณ, ประสานงานทะเบียน | ติดตามสถานะเอกสารได้ว่าค้างที่ใคร, ตัดยอดงบประมาณผูกพันอัตโนมัติ, นำเข้าข้อมูลนักศึกษา/เกรด |
| **Dean & Executives (คณบดี/รองคณบดี)** | กำหนดทิศทางนโยบาย, จัดสรรงบประมาณ, ติดตาม KPI ประจำปี | Executive Cockpit สรุปงบประมาณและผลงานวิจัยแบบเรียลไทม์, ระบบ Early-Warning คัดกรอง นศ. เสี่ยงตกออก |
| **System Admin (ผู้ดูแลระบบสารสนเทศ)** | จัดการสิทธิ์, ดูแลความปลอดภัย, จัดการการเชื่อมต่อ SIS/HRIS | ตรวจสอบ Audit Log, จัดการการซิงค์ข้อมูล, มีระบบสำรองกรณีระบบภายนอกมหาวิทยาลัยล่ม |

## 4. Scope & Feature Specifications (MoSCoW Framework)

### MOD-01: Unified Faculty Profile & TOR Engine
* **Must Have:**
  * `F01-01`: Single Profile & Dashboard แสดงประวัติ รายการสอน ผลงานวิชาการ และแต้ม TOR สะสม
  * `F01-02`: ระบบตั้งค่าเกณฑ์ภาระงานและน้ำหนักคะแนนตามประกาศคณะ/มหาวิทยาลัย
  * `F01-03`: แบบฟอร์ม TOR อัตโนมัติ ดึงข้อมูลชั่วโมงสอนและงานวิจัยมาคำนวณแต้มทันที
  * `F01-04`: One-Click Export แบบประเมินตนเอง (SAR/TOR) เป็นไฟล์ PDF พร้อมเอกสารแนบ
* **Should Have:**
  * `F01-05`: เวิร์กโฟลว์การตรวจและลงนามประเมิน TOR โดยหัวหน้าภาควิชาและกรรมการ
* **Could Have:**
  * `F01-06`: ดึงข้อมูลตีพิมพ์ภายนอกอัตโนมัติผ่าน Scopus / Crossref API จาก DOI

### MOD-02: OBE & Learning Outcome Tracker
* **Must Have:**
  * `F02-01`: โครงสร้างหลักสูตรและการแมปความสัมพันธ์ PLO $\leftrightarrow$ CLO
  * `F02-02`: ระบบบันทึกคะแนนตามเกณฑ์ Rubrics ที่ผูกกับ CLO (รองรับ Copy-Paste จาก Excel)
  * `F02-03`: Digital Evidence Vault จัดเก็บไฟล์ตัวอย่างข้อสอบและผลงานเด่นของนักศึกษา
* **Should Have:**
  * `F02-04`: คำนวณอัตราการบรรลุเป้าหมายการเรียนรู้ (Attainment Rate) รายบุคคลและภาพรวมรุ่น
  * `F02-05`: ระบบสร้างร่างเอกสาร มคอ.3 และรายงาน มคอ.5 อัตโนมัติจากข้อมูลในระบบ
* **Could Have:**
  * `F02-06`: Spider Chart วิเคราะห์จุดแข็ง-จุดอ่อนสมรรถนะนักศึกษาสำหรับอาจารย์ที่ปรึกษา

### MOD-03: Fast-Track E-Workflow & Budget Tracker
* **Must Have:**
  * `F03-01`: ดิจิทัลฟอร์มขออนุมัติโครงการวิจัย บริการวิชาการ และขออนุมัติเดินทาง
  * `F03-02`: ระบบสายการอนุมัติแบบกำหนดเงื่อนไขอัตโนมัติตามวงเงินงบประมาณ (Routing Rules)
  * `F03-03`: หน้าจอติดตามสถานะคำร้องแบบเรียลไทม์ (Visual Timeline & SLA Tracking)
  * `F03-04`: ระบบกันเงินงบประมาณผูกพัน (Encumbrance Ledger) ทันทีที่โครงการผ่านหลักการ
* **Should Have:**
  * `F03-05`: การแจ้งเตือนผู้อนุมัติและผู้ยื่นผ่าน LINE Notify และ Email
* **Could Have:**
  * `F03-06`: อัปโหลดและสแกนใบเสร็จ/หลักฐานเบิกจ่ายด้วย Basic OCR

### MOD-04: Executive Cockpit & Central Data Hub
* **Must Have:**
  * `F04-01`: Executive Dashboard สรุปยอดเบิกจ่ายงบประมาณ สถิติตีพิมพ์ และสถานะโครงการ
  * `F04-02`: Student Early-Warning Indicator คัดกรองนักศึกษาเกรดตกหรือเสี่ยงวิทยาทัณฑ์
  * `F04-03`: ระบบ Batch Sync ดึงข้อมูลจากระบบทะเบียน (SIS) และบุคคล (HRIS) ตามรอบเวลา
  * `F04-04`: หน้าจออัปโหลด CSV/Excel Ingestion เพื่อรองรับกรณีระบบกลางมหาวิทยาลัยขัดข้อง
* **Should Have:**
  * `F04-05`: ระบบ Export ตัวชี้วัดและสถิติรายภาควิชาตามมาตรฐาน สกอ./อว. ในรูปแบบ Excel
* **Could Have:**
  * `F04-06`: โมเดลพยากรณ์แนวโน้มการรับเข้านักศึกษาและรายได้คณะล่วงหน้า

## 5. Sample User Stories with Acceptance Criteria

### User Story 1: คำนวณภาระงาน TOR อัตโนมัติ (F01-03)
* **As a:** อาจารย์ผู้สอน
* **I want to:** ให้ระบบดึงตารางสอนจากระบบทะเบียน และงานวิจัยที่ได้รับอนุมัติ มาคำนวณแต้มภาระงาน TOR ให้โดยอัตโนมัติ
* **So that:** ฉันไม่ต้องเสียเวลานั่งนับชั่วโมงและคำนวณตัวเลขเองในแต่ละรอบประเมิน
* **Acceptance Criteria:**
  * **Given** อาจารย์เข้าสู่ระบบและมีข้อมูลสอนในภาคการศึกษาปัจจุบันใน Local Mirror DB
  * **When** อาจารย์กดปุ่ม "สร้างแบบประเมิน TOR รอบปัจจุบัน"
  * **Then** รายวิชาทั้งหมดจะปรากฏพร้อมจำนวนชั่วโมงและตัวคูณคะแนนตามเกณฑ์ที่คณะตั้งไว้
  * **And** แต้มภาระงานรวมจะถูกคำนวณและสรุปเป็นกราฟเปรียบเทียบกับเกณฑ์ขั้นต่ำทันที

### User Story 2: การอนุมัติโครงการและตัดยอดงบประมาณผูกพัน (F03-02, F03-04)
* **As a:** หัวหน้างานการเงินและพัสดุ
* **I want to:** เห็นยอดงบประมาณคงเหลือและงบผูกพันถูกปรับปรุงแบบเรียลไทม์เมื่อคณบดีอนุมัติโครงการ
* **So that:** คณะไม่ประสบปัญหางบประมาณติดลบหรืออนุมัติโครงการเกินวงเงิน
* **Acceptance Criteria:**
  * **Given** โครงการมูลค่า 50,000 บาท ถูกส่งถึงขั้นตอนคณบดีอนุมัติ
  * **When** คณบดีกดปุ่ม "อนุมัติ" พร้อมยืนยันรหัสผ่านหรือลายมือชื่อดิจิทัล
  * **Then** สถานะโครงการเปลี่ยนเป็น `APPROVED`
  * **And** ยอดเงินในหมวดงบประมาณที่ระบุจะถูกย้ายจาก `AVAILABLE` ไปยัง `ENCUMBERED` ทันที 50,000 บาท
  * **And** มีการบันทึก Audit Log ระบุผู้ทำรายการ วันเวลา และยอดเงินอย่างครบถ้วน

## 6. Non-Functional Requirements (NFR)
1. **Performance:**
   * หน้าเว็บโหลดสมบูรณ์ (P95) ภายใน $\le 1.5$ วินาที บนเครือข่ายอินเทอร์เน็ตปกติ
   * การประมวลผลคำนวณและ Export เอกสาร PDF ขนาดไม่เกิน 50 หน้า ใช้เวลา $\le 5$ วินาที
2. **Security & PDPA Compliance:**
   * การส่งข้อมูลผ่าน HTTPS (TLS 1.3) และเข้ารหัสข้อมูลจัดเก็บ (AES-256)
   * รองรับมาตรฐาน PDPA ของไทย: สิทธิการเข้าถึงข้อมูลเกรดและประวัติส่วนตัวตาม Role (RBAC)
   * Immutable Audit Trail บันทึกทุกความพยายามในการดูหรือแก้ไขเกรดและคะแนน TOR
3. **Availability & Reliability:**
   * Uptime ไม่น้อยกว่า 99.5% ในช่วงเวลาทำการ
   * สามารถทำงานต่อเนื่องได้ในโหมด Read-only/Local Data แม้ระบบเครือข่ายส่วนกลางของมหาวิทยาลัยจะขัดข้อง

## 7. Out of Scope for MVP (สิ่งที่ยังไม่ทำในเวอร์ชันแรก)
* การจัดทำระบบห้องสมุดดิจิทัลหรือระบบยืม-คืนอุปกรณ์ห้องแล็บ
* การทำ Mobile Native Application (iOS/Android) — ใช้ Responsive Web + LINE Webhook แทน
* การเชื่อมต่อระบบจัดซื้อจัดจ้างภาครัฐ (e-GP) โดยตรง (ใช้ระบบการเงินภายในคณะก่อน)
* ระบบ AI สำหรับตรวจข้อสอบอัตโนมัติ (Automated Grading)
